# PROTOCOL · your-interview 修复工程执行协议 v1.0

> 本文件是修复工程的最高执行规则，进版本控制、跨会话有效。
> 与任何历史聊天口径冲突时，以本文件为准。修改本文件只许 Forrest 或交接方（核查方）提交，执行者不得自改。

## 0. 角色与唯一接口

| 角色 | 职责 |
|---|---|
| **Forrest** | 唯一拍板人。待拍板事项只由他裁决；`main` 只由他点头合并。 |
| **执行者（WorkBuddy）** | 唯一开发执行线：按本协议从台账取票、实现、验证、推送、登记。 |
| **核查方（交接方）** | 独立核查：只认远端证据（`git ls-remote`、GitHub CI 结论、台账 diff），不认执行者自述。每 30 分钟一轮；异议登记在台账「核查异议区」并上报 Forrest。 |

**唯一接口 = 本仓库。** 任务、规则、状态、证据、待拍板事项全在仓库文件里流转。
聊天消息不构成任务、不构成证据、不构成完成。任何一方的会话中断/清零，不得丢失任何状态——状态只存在于仓库。

## 1. 事实源与优先级

1. 产品定稿：`docs/fix-program/source/specs/`（replica 定稿）——产品行为的唯一事实源。
2. 审查单：`docs/fix-program/source/AUDIT.md`（55 条）+ `docs/fix-program/source/tickets/`（全部票面）。
3. 任务台账：`docs/fix-program/FIX-STATUS.md`——队列与状态的唯一事实源。
4. 交接书：`docs/fix-program/source/HANDOVER.md`（背景参考）。

**冲突优先级：定稿 > 审查单/票面 > 现有代码。** 实现与定稿不一致 = 实现错。
撞到冲突：停下该票，在台账待确认区按格式登记（见 §7），继续下一票，不许自行裁量。

## 2. 状态机（台账中每票只许处于一个状态）

| 状态 | 进入条件 |
|---|---|
| `TODO` | 已入台账，未开工。 |
| `DOING` | 已认领，正在实现。全队列同时只许一张 DOING（串行清票）。 |
| `PUSHED` | 实现完成，提交已推远端（ls-remote 可见 sha），等待验证证据补齐。 |
| `VERIFIED` | §3 关票四步全部满足，证据已登记。等同已关票。 |
| `BLOCKED-DECISION` | 需 Forrest 拍板，已按 §7 格式登记，跳过不做。 |
| `BLOCKED-EXTERNAL` | 外部条件缺失（服务/账号/额度），原因与解除条件已登记。 |

终局时队列中只许存在 `VERIFIED` 与经 Forrest 书面豁免的票。

## 3. 关票四步（缺一不算关票，状态不许进 VERIFIED）

1. **实现**：按票面 + 定稿实现；与定稿冲突按 §1 停工上报。
2. **测试**：本票测试套件 + 直接邻居模块全绿；纯逻辑改动带单测（含边界）；提交信息写清测试数字（通过/总数）。
3. **活体证据**：活体验证结果留档（命令+关键输出，或截图路径），指针写进台账该票一行。
4. **远端确认**：push 后以 `git ls-remote` 确认 sha 已在 `develop-new-features`；台账登记 sha + 测试数字 + 证据指针。没到远端，不许报完成、不许进 VERIFIED。

## 4. 启动与断点恢复（每次开始工作/任何中断后，第一动作固定）

1. `git fetch` 并确认 `develop-new-features` 远端 tip sha。
2. 读本协议 + 台账全文。
3. 状态对账：台账中 `DOING` 的票若无对应远端提交，按未开工处理（回 `TODO`）；`PUSHED` 未登记证据的先补验证。
4. 从最高优先级的 `TODO` 认领一张置 `DOING`，立即干活，不等任何确认。
5. **首次启动**额外要求：在台账顶部「运行回执」区写入三数——远端 tip sha、未完成票总数（TODO+DOING+PUSHED+BLOCKED 计数）、当前运行模型名。

**中断前落盘**：每完成一步就 commit + 更新台账。任何中断最多丢失一张票的半程进度；恢复后按上述 1–4 步续跑，不重做已 VERIFIED 的票，不跳步。

## 5. 队列顺序与范围锁

- 顺序：审查 S2 → S3 → S4 依次清；票 94（网关健康）随主线；票 16 第二道复验须在 81–84 落定后做；票 21 欠独立真人化验收，排在主线后段。
- **票 68、票 73 = BLOCKED-DECISION**：跳过，等 Forrest 在台账待确认区裁决。
- **B 组锁定**：票 90/91/92 在主线队列清零（除 BLOCKED-DECISION 外）之前一律不开工。
- 88–94 号票按既有票面执行；91 号专指覆盖率二期，票 34 衍生事件补发不得再占用 91 号。
- 范围外的新想法（新功能、重构冲动、版本规划）一律只进台账「候选区」，不进队列、不实现。

## 6. 推送与 CI 节奏

- 只推 `develop-new-features`；永不直推 `main`；永不自行开 develop→main 的合并（PR 只在 §8 终局时开备审）。
- 攒批推送：一票一推为常态；避免连推把上一轮 CI 顶掉取消——**取消 ≠ 绿，也 ≠ 红**；关键节点（每批最后一票）等一轮完整 CI 结论（Backend/Frontend/E2E）再继续。
- 推送被拒/鉴权失败：先查远端 tip 是否已含该提交（防重复推），再按 BLOCKED-EXTERNAL 登记，不许换着花样重试超过 2 次。

## 7. 待拍板与上报格式（台账待确认区，每条固定四行）

```
票号 / 问题（一句话） / 选项（A/B，各一句利弊） / 我的推荐（+一句理由）
```

- Forrest 的裁决由他本人或核查方登记进台账后生效，执行者据登记执行。
- 卡住超过一轮工作仍无解 → 同样格式登记，不许静默停摆：**停摆必须留痕**。

## 8. 完成定义（终局，缺一不算完成，任何人不许提前宣布）

1. 队列清零：每票 `VERIFIED`（sha + 测试数字 + 证据指针齐全）或经 Forrest 书面豁免。
2. 正式验收包 `docs/fix-program/ACCEPTANCE.md`：55 条逐条判定表（判定 + 证据指针）、独立真人化验收记录（含票 80 场景与未测格明示的覆盖地图）、全量测试数字与关键模块覆盖率（≥80%，逐个列明）。
3. 台账全量对齐：状态、sha、数字与远端一致，无一号两用、无过时描述。
4. 开出 develop→main 的 PR 备审，标题注明「待 Forrest 批准」。
5. `main` 的合并只由 Forrest 本人执行/点头；执行者与核查方都不许合、不许催合。

## 9. 失败模式预置（出现 X → 执行 Y，不临场发挥）

| 情形 | 动作 |
|---|---|
| 429 / 额度限流 | 先把当前进度 commit + 台账落盘，再停；恢复后按 §4 续跑。 |
| CI 轮次被后续推送取消 | 不当红也不当绿；以关键节点那一轮完整 CI 为准。 |
| CI 真红 | 先按顺序排查环境伪影（服务未起/schema 未建/框架程序集缺失），实证排除后再怀疑代码；确属代码问题按缺陷处理并登记。 |
| 票号撞车/一号两用 | 立即停用混淆号，在台账用一节说清真相与处置（如 81–84 先例），编号只增不复用。 |
| 沙盒/环境清零 | 一切只认仓库：重拉仓库即可完全恢复状态；禁止把任何事实源只存 /tmp 或本地。 |
| 推送结果不明 | 先 ls-remote 核对再决定是否重推，禁止盲目重复推。 |
| 需求/定稿冲突 | §1：停该票、登记待确认、继续下一票。 |
| 连续两轮无任何推进 | 在台账登记原因（BLOCKED-*），不许无声消失。 |
