# 票 92 — OCR 准确率金标准回归集 + 三个入口接全共享管线（系统提升 B3，修复收官后开工）

严重度：S2（OCR 是"智能粘贴"的核心卖点，但当前存在**入口未接**与**无回归保护**两个问题）
来源：Forrest 补充任务单 B 组 B3（2026-10-23）

## 事实
- 现有实测水位：关键串抽取 **8/8**、字符准确率 **99.2%**——这是要守住的底线，不是起点。
- **已知缺口（本沙盒内代码核实）**：`SmartParseRules.cs` / `SmartAddHandlers.cs` 中，图片类粘贴走的是**诚实 `Failed`（未接 OCR）**路径，UI 回落手动录入。即"JD 截图 / 图片简历 / 题目截图"三个入口目前并非都接到 OCR 管线上。
- 目前**没有 OCR 准确率回归集**，改解析或换 OCR 后端时无法判断是否劣化。

## 任务
1. **建金标准集**：采集真实截图，分四类入口——邮件邀请 / JD 截图 / 图片简历 / 题目截图；每类若干张，附人工标注的期望文本（ground truth）。
2. **回归指标与每次必跑**：字符准确率 + 关键字段抽取率（公司/职位/地点/薪资/时间等）。守住现有水位（关键串 8/8、字符 99.2%），**低于即红**。
3. **按 platform-ocr-spec 确认共享管线**：JD 截图、图片简历、题目截图三个入口必须走**同一条**共享 OCR 管线；目前没接的接全，不许各入口各写一套。
4. 回归集接入：改解析规则或改 OCR 后端时必须跑（由票 88 CI 或独立脚本强制）。

## 验收
- 金标准集落盘（图片 + 期望文本 + 抽取结果快照）。
- 每次跑输出两个数字（字符准确率、关键字段抽取率）并与基线比较，**降了就是红**，不许用"差不多"放行。
- 三个入口经代码核实确实共用同一管线（给出代码位置证据），未接的已接全并有实跑证据。
- 反向验证：人为劣化 OCR 输入（如降质截图）或改坏抽取规则，回归集必须红。
- 证据落盘：`docs/fix-program/evidence-92/`。
