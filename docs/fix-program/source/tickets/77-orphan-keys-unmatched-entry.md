# 票 77 — 孤儿键后缀匹配不上现存条目时被静默跳过、永不归档（S3，源：票 15 独立复验 A6/F1）

## 复现（独立验收 agent 实测，evidence-15/independent-acceptance.md A6 节）
预置 `pb.debrief.<随机串>`、`pb-pasted-<随机串>`（后缀不是任何现存条目 id）
→ 登录打开 Playbook、跨页导航、刷新：前端从不发出归档请求，两键原样留
在 localStorage；API/DB 查无归档。对照组：后缀换成真实条目 id 时，
legacy-debriefs/legacy-pasted 的 import 与读回逐字一致、完全正常。

## 问题定性
票 15 的归档设计以「后缀 = 条目 id」为前提，只归档能匹配现存条目的键。
但孤儿键的典型成因正是条目已被删除——最需要归档保全的一类恰被跳过，
且静默无提示。清缓存即永久丢失，与「无损归档」目标有缺口。

## 任务
- legacy import 改为不依赖条目存在性：以后缀原文为归档键落库（归档表
  本就存 Key/EntryKey 形态时最小改动；若现表结构强绑 EntryId 外键，
  先报协调者给两个解法，不要硬改）。
- 已归档（匹配条目）的既有行为与读回口径不变；导入打标/幂等口径不变。
- §7 单测：随机后缀归档成功、重复导入幂等、跨用户隔离、空值/超长
  payload boundary。

  清 localStorage 后归档仍在；真实条目 id 变体回归不破。
- Interviews.Tests 不回退（基线 184）。
