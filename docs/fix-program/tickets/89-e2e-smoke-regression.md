# 票 89 — E2E 冒烟回归套（Playwright）（系统提升 A2）

严重度：S2（护航项——前端当前零自动化测试，87 张票的 UI 面改动至今只能靠人肉点击验证）
来源：Forrest 补充任务单 A 组 A2（2026-10-23）

## 事实（已核实，2026-10-23 沙盒内）
- 前端**零自动化测试**：`web/` 下无 `e2e/`、无 `@playwright/test` 依赖、无 `*.spec.ts` 的测试运行器配置（前端 Jest 亦未接入，相关票为票 64）。
- 当前 UI 验证方式 = 人工在浏览器点，或 curl 打 API 层。**API 层验证不到的东西正是缺陷高发区**：徽章文案、分组归属、热力图格子着色、卡片成卡与否——这些全是 DOM 呈现，curl 无从判断。
- 已有 8 个后端微服务 + 网关 + Angular dev server 在沙盒内跑通（端口 5200 / 5262-5268 / 4200），具备 E2E 运行环境。

## 任务
1. 在 `web/` 下建 Playwright 套件（`web/e2e/`），依赖 `@playwright/test`，一条命令 `npm run e2e` 跑完并出截图报告（`trace: 'on-first-retry'` + 失败截图 + html report）。
2. 套件自带**依赖等待与服务健康检查**：跑之前等网关 `/health/live` 与前端 4200 就绪；任一未就绪则明确报错退出（不许在半起状态下跑出假绿/假红）。环境起法本身不在本票范围（B4 落地后切到一条命令）。
3. **测试账号与数据隔离**：用独立种子账号（非 admin），测试内建的数据跑完即清理。E2E 不许污染真实数据，也不许依赖他人遗留数据。
4. 覆盖黄金路径（每条一个 spec，逐条独立可跑）：
   - **E2E-1（首个用例，票 80 场景）**：Playbook 详情页——造一个**无轮次、无 Result** 的条目，断言**头部徽章文案与左侧分组归属一致**（都应走"进行中"口径，不许出现徽章 Completed 而分组在 In Progress）。
   - E2E-2：登录 → Tracker 建单（手工/智能粘贴各一条）→ 编辑保存 → 列表可见。
   - E2E-3：Playbook 条目 → 加轮次 → 待办勾选 → 状态与持久化正确。
   - E2E-4：Tech Stack 复习（Log review）→ 热力图当日格着色 → 刷新保持（**顺便作为票 81 的界面级活体验证载体**）。
   - E2E-5：OCR 入口成卡（上传截图 → 解析 → 成卡）。
5. 断言一律以**用户可见结果**为准（DOM 文本/可见元素/着色 class），不许断言内部 signal 或 API 响应冒充 UI 验证。

## 验收
- **一条命令**：干净环境（依赖已装）下 `npm run e2e` 跑完全部黄金路径，产出 html 报告 + 截图。
- **反向验证（核心，必须做）**：人为打坏任一黄金路径（例如把 E2E-1 的 statusText 改回默认 `Completed` 兜底、或把 E2E-4 的 `recordReviewActivity()` 调用删掉），套件**必须红**且失败截图能一眼看出坏在哪。只验"绿能绿"不算验收。
- E2E-1 的红/绿结果直接作为**票 80 的界面级证据**归档（票 80 票面已写明该场景是"永久回归任务"）。
- E2E-4 的红/绿结果直接作为**票 81 的界面级活体验证证据**（补 API 层 curl 验证的不足）。
- 证据落盘：`docs/fix-program/evidence-89/`（spec 全文、报告、正常与打坏两次的截图）。

## 依赖与阻塞
- **E2E-5（OCR）**：OCR 依赖外部/云端 OCR 服务。若沙盒无可用凭据，本条用例须**显式标记为 skip 并写明原因**，不许删掉用例、也不许用假数据让它假绿——没验就是没验。
- **推送权限**：同票 88，当前 GitHub PAT 失效，套件代码要入远端需新 PAT。
- 本票不改动产品代码（打坏验证用的改动必须是临时、在验证后还原的）。

## 不变项

- 不动后端（套件只做黑盒 UI 验证）。
- E2E-1 若跑出来是红的，**不许改断言去迁就现状**——红说明票 80 未修，应报协调者立/推进票 80，本票只负责如实呈现红色并保留证据。
