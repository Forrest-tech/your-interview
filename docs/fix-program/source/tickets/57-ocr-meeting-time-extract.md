## 复核结论（协调者已实证，evidence-57/repro-before.txt）

- 父 agent 担心的「只吃 body 字段」陷阱在生产**不存在**：AiGateway `ExtractImageText` 只回全文转写（`ImageTextDto.Text`），前端 `parsePastedEmail` 的 `p.body` = 全文去掉顶部头区块的余部，会议邀请卡在其中（两形态实测 body 均含卡片行）。
- **但会议时间实际仍抽不到**：真实样本卡片行 `2026-10-13 周二 10:00～11:00` —— `extractInterviewWhen` 的 ISO 正则要求日期后紧跟时间，中间隔着「周二」即不匹配；英文月份正则也不覆盖。生产形态（Key:value 头 + 卡片）实测 `when=null`。
- 注意：绝不能改成对全文跑抽取——全文含 `Sent: 2026-10-08 09:18`，会误抽发信时间当面试时间（实测已证）。抽取域保持「去头后的 body」不变。

## What to build

扩展 `extractInterviewWhen` 覆盖邀请卡常见格式，保持既有格式不回归：
- `2026-10-13 周二 10:00～11:00`（星期夹在日期与时间之间、全角波浪号时段）→ `2026-10-13 10:00`
- `2026年10月13日 14:00` / `2026年10月13日星期二 14:00～15:00`（年月日写法）
- 既有：`2026-10-07 11:00` ISO、英文 `Oct 7, 2026 at 11:00 AM` 口径不变
- 多个候选时间共存时不得抽中邮件发送时间（抽取域仍是去头 body，此条是防回归护栏）
