# 票 70 — Knowledge 详情双页签编辑静默覆盖（S3，跟进票，源：票 61 独立真人化复验 D3）

## 复现（独立验收 agent 实测，证据 evidence-61/independent-acceptance.md + ind-* 截图）
1. 同一账号在两个浏览器页签打开同一条 Knowledge 条目详情。
2. 页签 A 修改 Concept 保存成功。
3. 页签 B（仍持旧数据）修改另一字段保存 → 同样成功，A 的 Concept 改动被
   静默覆盖丢失：无冲突提示、无 409、无任何警告。
（question 字段未受影响——票 61 的护栏只防空值，不防旧值覆盖。）

## 任务
1. 先盘点口径：Knowledge 实体/DbContext 是否有 xmin 并发令牌；Update handler
   保存时是否可能抛 DbUpdateConcurrencyException（若抛了，前端为何没呈现——
   票 07 的 409 映射是否覆盖 Knowledge 服务）。盘点结论入证据。
2. 目标行为：后保存者收到明确冲突反馈（409 + 前端冲突提示，参照票 07
   concurrency_conflict 呈现口径），先保存者的数据不被静默吞掉。
   若盘点发现全站多个服务同病，先只修 Knowledge 并在报告中列出同病清单，
   不许扩大范围自行全改（另行立票由协调者排）。
3. §7 单测：Handler 级并发用例（两上下文同读→先存→后存应冲突失败），
   含不变项（单页签正常编辑保存不受影响）。

## 验收
- 活体双页签复现：修复前后对照（前：静默覆盖；后：后存者得 409 提示、
  先存数据完好）。
- Knowledge.Tests 不回退（基线 22）；受影响套件全绿。
- 不变项：票 61 的 question 空值护栏行为不变；其他字段的正常编辑不变；
  不引入全局异常处理改动（若需动 BuildingBlocks 映射，先报协调者）。
