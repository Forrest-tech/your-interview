# 平台能力：共享 OCR 服务（2026-10-21 用户定方向 + 同图对测选型）

## 定位
- OCR 是**全系统平台能力**，不是某个模块的私有功能：一个共享服务、一个统一接口，各模块调用，禁止各模块自攒 OCR 实现（全局规则：同一份底层能力、多视图）。
- 消费方（已知）：Playbook 材料入口（邮件截图，定稿第九节）、Tracker/Smart paste（JD 截图）、Resume（图片型简历转文本）、Tech Stack/备考（题目与文章截图）。

## 选型（2026-10-21 同图对测，证据：fix-verify/system-audit-20261021/ocr-test/AB-RESULT.md）
- **主引擎：PaddleOCR（PP-OCRv6），原图直跑，禁止放大预处理**（2× 放大实测更慢且更差：97.5% vs 99.2%）。关键串与 DeepSeek 基本同级（8 串 7 逐字、1 仅全角～半角化、数值零错误），签名 Khalil 读对（DeepSeek 误读 Khalii）。
- **DeepSeek 视觉为辅**：低置信/解析失败时兜底复核；或只吃 OCR 纯文本做结构化抽取（截图不出本地）。系统其余 LLM 任务（备考生成、面经整理）继续走 DeepSeek key。
- OCR 输出处理层（服务内）：置信度/位置过滤图标噪声行、标点归一（全角～等）、按行坐标还原阅读顺序；字段结构化由消费方的既有解析规则完成。

## 接入约束
- 延迟必须在**目标部署机复测**后定同步/异步：沙盒 2 vCPU + paddlepaddle 3.3.1 OneDNN bug 需 `enable_mkldnn=False` 绕行，单图 76.6s 属环境特例，不可作生产依据；接入时锁定 paddle 版本或保留开关，并评估 PP-OCR 轻量模型变体的速度/精度平衡。
- 服务形态：独立小服务挂网关后（与 AiGateway 并列或其内部通道），接口只收图片、返逐行文本+坐标+置信度；无状态。
- 数据纪律：截图默认不出本地（主通道全本地）；仅兜底复核时才把图发 DeepSeek，且要在消费方预览里如实标注来源（与第九节口径一致）。
