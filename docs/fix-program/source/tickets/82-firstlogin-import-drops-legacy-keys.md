# 票 82 — 首登路径旧数据导入失效且静默清旧键（S3，源：票 16 第二道独立复验 F2）

## 事实（evidence-16/independent-acceptance.md 续写节，T5）
复现场景：新账号在**未登录状态**预置旧键 ts.customCategories /
ts.reviewActivity → 登录 → 打开 Tech Stack：两度实测均无 import 请求、
旧键被清、服务端零行。对照法（登录后植入旧键再刷新）全过：import 两
端点 200、分类/活动可见、再刷新不重复。
即导入本体与防重没坏，**首登路径失效，且失败时仍把旧键清掉（静默丢
数据）**——与票 14/15 的同型导入路径一并核查（若为共享模式问题，
在本票说明其余两面是否同病）。

## 任务
- 定位首登路径导入触发时机为何错过/失败（未授权时初始化先跑、导入
  标记提前置位、异常吞掉后仍清键等，读码+复现定责）。
- 修复原则：**导入成功落服务端后才清旧键**；失败保留旧键待下次重试，
  不许静默丢。

## 验收
- 按上述复现场景全流程过（分类与活动均导入、热力图着色）。
- 登录后植入+刷新路径不回退；防重（多次打开不重复导入）不回退。
- 票 14（Jobs 面）/15（Interviews 面）导入路径同场景抽验结论入报告
  （同病则在本票一并修或另行立票报协调者）。
