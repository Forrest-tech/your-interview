- 左：公司 / 岗位 / 状态徽章；投递日期·来源·准备度；Recruiter + 最近联系。**元信息字段常驻显示（2026-10-21 用户明确，覆盖 X1 的隐藏处理）：投递日期 / 来源 / 准备度 / Recruiter / 最近联系五项永远在位，无值时显示占位符「—」，不整项隐藏。** **Recruiter 口径（2026-10-21 用户裁决）：= 最近一封邮件/沟通的发件人（recruiter 本人，如 Khalil），不是各轮面试官汇总；面试官只在各轮内逐人呈现。**
- **四格条（JD 摘要/公司/简历/Resume Score）整行通栏（2026-10-21 用户要求）：占满上区全宽，不限于左列；按钮行在其下方，为上区最后一行。**
- 右：「下一步」卡（由轮次/沟通状态推导）——**只有标题+提示文字，无行动按钮**（2026-10-21 用户决定：原 Go prepare 按钮点击无反应且与轮次导航重复，删除；导航靠 stepper）。
- 下方四格条：JD 摘要 / 公司 / 本投递简历 / Resume Score，每格可展开看全文。此四格条即岗位信息，**不再有独立"岗位信息"页签**。Resume Score 的说明行收在四格条容器内部底部，不许飘出框外。展开全文在展开区内显示，**展开区高度封顶（min(420px, 45vh)）+ 内部滚动条（10px、轨道 #e7eaee、滑块 #7d8797、hover 强调色），不撑长页面**（2026-10-21 用户定，设计稿图已确认）。头部左列间距紧凑，元信息与四格条之间不留空带（2026-10-21 用户）。
- 按钮行（＋ 添加材料 / AI 模拟面试 / 打开岗位 JD）位于**四格条下方**、上区容器最后一行（2026-10-21 用户调整：信息在前、操作在后）。Edit/删除进右上 kebab。
- 视觉分块（2026-10-21 用户）：上区（头部整块）与下区（页签+stepper+Round 卡+复盘）各自用明确实线边框围成整体，间距分明。
- 旧页面的双头卡、7 个页面级页签（Overview/Rounds/Guidance/Q&A/Analysis/Assets/Edit）全部取消。

## 二、添加材料 — 条目级唯一入口
- 位置：条目头按钮打开（页面顶部展开区）。Round 内、沟通记录内**不设**独立入口；仅在 Round 的材料页签留「＋ 添加到本轮」快捷链接（打开同一入口、归属预设本轮）。
- 类型只有三种：**邮件 / 录音·转写文本 / 备注**（电话已并入录音·转写/备注；截图不是类型，任何类型内都能粘截图，原图作为该材料的附件保留。**截图进入方式（2026-10-21 用户明确）：只有粘贴——直接粘进文本框，文本框既能输入/粘贴文字、也能粘贴图片，粘入的图片在框内以缩略图预览（可移除/替换）；面板不设单独的截图文件选择按钮。**）**「录音·转写文本」内部是明确二选一呈现（2026-10-21 用户强调）：分段切换「上传录音」|「粘贴转写文本」，一次只显示一种输入，不上下堆叠；保存只取当前选中的一种来源；粘贴音频文件自动切到上传模式、粘贴文本（另一模式为空时）自动切到文本模式。**
- 流程：选类型 → 粘贴（文字/截图/拖文件）→ **解析预览（可改）→ 归属确认 → 保存**。**面板不设标题输入框（2026-10-21 用户决定）：标题一律保存时自动生成——邮件取主题、录音取文件名、转写/备注取首行摘要。模式说明文字按当前模式显示（上传模式只讲录音、文本模式只讲转写格式），不合并混写。**
- 邮件：先分类（邀约/改期/拒绝/跟进）再按类型提取字段；发件人+时间+主题重复 → 提示已存在。
- **归属确认**：系统按内容建议（某轮 / 沟通记录 / 新建 Round），下拉可改。选新建且提取到时间 → 同时建 Round + 应用内日历 + 提醒（提前 1 天 + 提前 1 小时）。邀约时间同步对应轮次时间。（注：.ics 导出于 2026-10-21 用户决定取消——只有应用内日历，不做导出到系统日历。）
- 通话类（安排性质）识别后归属默认建议沟通记录。
- **材料可改归属**：材料卡带归属下拉，保存后可在轮次 ↔ 沟通记录间移动。

## 三、页面页签 + 轮次导航
- 页面级页签只有两个：**轮次 / 沟通记录**。沟通记录有未处理安排时：页签红点 + 数字，轮次页顶部横幅提示并可跳转处理。
- 轮次导航条（stepper）：每格 = Round N · 日期 / 阶段 / 状态 / 综合分；＋添加 格。一屏只展开一轮。
- 默认选中：有未开始的轮次选它，否则最近一轮。默认页签按阶段：未开始 → 备考报告；已结束 → 面试实录。

## 四、Round 工作卡
- 头：阶段 + 状态徽章 / 时间 / 面试官（真名逐人）/ 形式；日历条（已加入日历 + 提醒 + 编辑）。（.ics 导出已取消，见第二节注。）
- 内页签顺序固定：**备考报告 → 面试实录 → 问答入库（计数）→ 材料（计数）**。

### 4.1 备考报告
- **数据获取是系统 AI 集成能力，不是独立按钮（2026-10-21 用户定）：删除「Search interview experiences」「Glassdoor interviews」这类手工按钮入口。改为：在设置中配置启用哪些数据源（面经来源、Glassdoor、公司背景、题库匹配等，可含搜索服务配置），生成备考时系统按公司 + 岗位自动匹配并抓取已启用的数据源，结果如实标注在 Sources 行（已抓取 / 未启用 / 未配置分别呈现，不假装）。**
- **默认即有框架内容（2026-10-21 用户强调）：未点生成时也必须呈现按面试流程排布的标准框架（八段结构 + 通用要点），不得是空表单；生成/重新生成是在框架基础上结合六类输入做个性化，不是无中生有。框架默认内容走三语 i18n，不写死中文。**
- **语言一致（2026-10-21 用户强调）：备考报告（含 AI 生成内容与默认框架）语言必须与系统语言（账号 preferredLanguage）一致，不得默认中文。**
- 六类输入：JD、公司背景、全网机经、**本投递的 tailored 简历**、过去类似岗位面试原题、用户技术短板。（机经 v1：粘贴 + 题库聚合，不做真实联网搜索。）
- 按模拟面试流程排布：开场寒暄 → 听对方介绍（记什么/怎么回应）→ 自我介绍（60 秒 + 2 分钟两版稿）→ 项目深挖 → 技术问答 → 行为题 STAR → 反问环节 → 收尾与注意事项。结构借鉴 2026-10-08 Corpay Experience 备考稿。
- **左侧要点目录**：点击锚点定位、滚动高亮当前段；导出文件同序。
- 每题：北美标准答案口语版 + 技术版；可播放（复用 AI Practice 的 TTS：`web/src/app/features/ai-practice/tts-audio-cache.ts`，IndexedDB `your-interview-tts`，按 text+voice+lang 缓存；口语版播放时当前句高亮）；可编辑（用户版优先，AI 原版保留可还原，标「已按你的版本」）。
- **与 Tech Stack 双向同步**：题已在 Tech Stack → 答案直接取 Tech Stack 那份，在此处编辑保存即同步回 Tech Stack；题不在 → 卡上分类下拉 + 「＋ 加入 Tech Stack」，加入时自动带来源标签 **公司 · Round**（对齐 Tech Stack 的 asked sources 模型），**并带上该题标准答案作初始答案（用户编辑版优先，其次 AI 技术版）（2026-10-21 用户裁决）**。短板相关题置顶并标红。

### 4.2 面试实录
- 转写**按段存储**：说话人（真名逐人）+ 原文 + 起止秒（有录音时来自 Whisper segments）。说话人分不清先标「面试官 1/2」，可从本轮面试官名单批量改名、全篇生效。
- 录音是**一整段不切分**；每段带 ▶ 点击 seek 到该段播放；常驻播放条（进度/倍速/连播·只播本段切换）；播放时当前段高亮。
- 纯文本段（无录音）：无播放钮；**发音维度不评分**、不猜测，明示原因。
- 顶部字号控件：− / 百分比（可点击输入）/ ＋，与 AI Practice 共用 localStorage 键 `user_practice_zoom`；**只作用于问题与答案类文本**，界面框架不变。
- 整轮总览：综合评分 + 通过概率（明确标注 AI 估计并附依据）+ 最强项 + 最大短板。
- **逐题多维分析卡**：维度 = 切题性 / 技术深度 / 表达 / 发音；每维度 = 分数 + 客观评语 + 改法。硬规矩：评语每句判断必须给依据（引用原话 / 时间点 / "全段未出现 X"），无依据不写。旧的"好的地方/弱点"两列取消。
- 每题下方：北美标准回答（口语版 + 技术版），播放/编辑规则同 4.1。
- 回答原文恒标"原文 · 未修改"；导出按钮打开统一导出对话框。

### 4.3 问答入库
- AI 从实录抽问答对：标提问人（真名）+ 本题得分 + 默认分类（下拉可改）。技术题默认勾选，行为题默认不勾（用户定默认⑤：AI 推荐默认勾选、行为题除外）。
- 逐条确认或批量加入 Tech Stack，来源标签 = 公司 · Round · 日期。

### 4.4 材料
- 本轮全部原始件：邮件（解析字段 / 原文 / 截图 三视图切换）、录音、转写、备注、截图。
- 旧 Before/After 等历史数据全部并入此处展示，不丢数据。**Before/After 判定（2026-10-21 用户裁决）：按材料日期与所属轮次日期比较自动判定（轮次日期之前 = Before、之后 = After）；无日期可比时回落旧规则（邮件 Before、其余 After）；存量材料按同一规则在展示时纠正，不做数据迁移。**
- 每件材料带归属下拉（改归属）。

## 五、沟通记录（条目级页签）
- 内容：不属于任何一轮的沟通——协调电话（录音/转写/要点经统一入口归属至此）、往来邮件、备注。时间线展示，与 Tracker 邮件时间线是**同一份底层数据**（两处可看，不复制）。
- 每条支持 AI 摘要；提取到新安排 → 一键创建对应 Round 并关联；重复安排不重复建；状态：未处理 / 已处理（建轮次、改期同步、忽略）。
- 例外：带问答评估的电话（如 Phone Screen）本身是一轮 Round（判断标准：有没有人在评估你），不放这里。

## 六、统一导出对话框（面试实录与备考报告共用）
- 内容勾选：对话原文（必选锁定）/ 逐题分析 / 标准回答（用户编辑版）/ 总评分与通过概率。**时间戳不是选项**：原文自带，恒显示恒导出。
- 格式四选：PDF / Word(.docx) / JPG 长图 / Markdown。
- 位置：**仅下载到本机**（无"存入材料/Documents"选项）。
- 文件名：可编辑输入框，自动生成「公司-RoundN-实录-日期」（备考报告为「…-备考-日期」），扩展名随格式自动变。
- 记住上次的内容/格式选择。

## 全局规则
- 同一份底层数据，多模块只是视图；打通只 additive，不隐藏/不替换范围外既有功能；旧数据必须在新布局可见。
- 5 条默认（设计稿按此，用户未否决）：①截图解 析走现有 AI 网关视觉读图；②日历=应用内日历 + 提醒（.ics 导出已于 2026-10-21 取消，见第二节注）；③机经 v1 粘贴+聚合；④标准回答技术版每题生成、口语版按需生成（实现时可两版都生成，播放/编辑行为一致）；⑤问答入库 AI 推荐默认勾选、行为题默认不勾。

## 七、Playbook 列表页分组（2026-10-21 用户拍板）
- 上方 **In Progress**（现状不变），下方一个 **Completed** 区：流程已走完的条目自动归入（归类依据 = 条目最终结果落定，如被拒 / Offer / 通过 / 放弃；轮次全结束但还在等回复的**不算**完成，仍留 In Progress）。
- Completed **默认折叠**，标题带计数；区内按结束时间倒序。
- 每张 Completed 卡带醒目**结果徽章**（结果原文 + 语义色：被拒红、Offer 绿、其余中性/蓝）；不按结果再分小节（数量少时太碎，用户已否决）。
- 现有公司/状态筛选对两区同时生效。

## 八、详情页左侧条目导航（2026-10-21 用户要求）
- 详情页左侧加一条目导航栏：全部条目列在左侧，按 **In Progress / Completed** 分组（与第七节同一归类口径、同一实现），当前条目高亮，点击直接切换条目，不必返回列表页。
- 导航与详情页放宽是同一个布局：左导航 + 右内容，整体用满宽度。
- 导航列表的样式（字号、条目样式、分组标题）与站内其它页面的列表保持一致，不另 invent 一套。

## 九、多图粘贴与邮件批量解析聚合（2026-10-21 用户要求）
- **多图共存**：统一入口的截图从「单张、新粘替换旧」改为**多张追加**：框内缩略图条可容纳多张（每张带文件名/大小/单独移除），再粘只追加、不替换、不弹「已替换」提示。此变更覆盖此前 verify 断言里的替换语义（断言随定稿改）。
- **批量解析（Email 类型）**：Parse preview 对全部截图逐张走视觉 OCR（全局规则①）→ 抽 From/Date/Subject/正文；文字框有文字时仍以文字为内容来源、截图作附件（单图 OCR 打通是本节前置，同批实现）。
- **预览聚合**：批量预览按**主题聚合**（主题归一化：剥 Re:/Fwd: 等前缀后比对）分组，组内按邮件时间**正序**（早→晚）排列，组间按组内最新时间倒序；每张卡可单独改抽出字段、单独移除；与既有沟通在主题+时间+发件人上疑似重复的，卡上标「疑似重复」提示，不自动丢弃（用户定夺）。
- **逐张容错**：单张 OCR 失败只标该卡失败（可重试/移除），不拖垮整批。
- **保存与呈现**：保存后每封邮件各成一条沟通记录、同主题共用同一聚合标识；详情页 Communications 按**主题聚合展示、组内时间正序**，呈现一条完整的往来记录，而非散条平铺。聚合只影响展示与归组，不改底层单条数据模型（全局规则：同一份底层数据）。
